# Correção de Bug

**Data:** 2026-07-10 21:00
**Referência:** Relatório do usuário — WhatsApp 401/404 no QR Code

## Problema
WhatsApp não conecta. Console mostra:
```
GET /api/whatsapp/connections/5130ae9a-.../qrcode → 401 (Unauthorized)
GET /api/whatsapp/connections/5130ae9a-.../qrcode → 404 (Not Found)
```
O QR Code nunca aparece. Usuário não consegue escanear.

## Causa Raiz
**3 bugs encadeados:**

1. **Backend `getQrCode` retorna 404 quando Puppeteer não inicializou** (`whatsapp-connections.controller.ts:116`)
   - `connectConnection` retorna imediatamente (fire-and-forget) e inicia Puppeteer em background (10-30s)
   - Frontend começa a polling `/qrcode` imediatamente
   - `getConnectionStatus()` lança erro se a connection não está no `Map` do runtime → 404

2. **Frontend polling sem delay** (`WhatsAppConnectionsPage.tsx:162`, `WhatsAppPage.tsx:332`)
   - Polling começa 2s após `POST /connect`, mas Puppeteer leva 10-30s para gerar QR
   - Primeiras ~10 requests sempre retornam 404

3. **Erros de auth silenciados** (`catch { /* ignore */ }`)
   - Se token expira durante polling, 401 é ignorado silenciosamente
   - Usuário vê "Tempo esgotado" sem saber que é problema de autenticação

## Solução Implementada

### Arquivos modificados
- `backend/src/modules/integrations/whatsapp/whatsapp-connections.controller.ts`
  - `getQrCode`: catch agora verifica DB antes de retornar 404; se existe mas não está no runtime, retorna `{ initializing: true }` em vez de 404
  - `getConnectionStatus`: mesmo tratamento — retorna estado `UNINITIALIZED` em vez de 404

- `frontend/src/pages/WhatsApp/WhatsAppConnectionsPage.tsx`
  - Polling agora espera 3s antes do primeiro request ( Puppeteer init time )
  - Intervalo aumentado de 2s para 3s
  - Timeout aumentado de 45s para 60s
  - Trata `data.initializing` do backend (mantém status 'initializing')
  - Erros 401/403/404 param o polling e mostram mensagem clara ao invés de ignorar

- `frontend/src/pages/WhatsApp/WhatsAppPage.tsx`
  - Mesmas correções: delay 3s, intervalo 3s, trata `initializing`, trata erros 401/403

### Decisões técnicas
- **`initializing: true`** no response: permite ao frontend distinguir "Puppeteer carregando" de "erro real"
- **3s delay + 3s interval**: balanceia responsividade com sobrecarga do Puppeteer
- **60s timeout**: tempo máximo realista para Puppeteer + QR scan (era 45s, insuficiente em máquinas lentas)
