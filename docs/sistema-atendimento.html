Visão Geral

Sistema de atendimento profissional inspirado em Zendesk, Freshdesk, Jira Service Management e Intercom. Inclui timeline visual, métricas de IA, chat responsivo, inteligência artificial para alertas, gráfico temporal, dashboard histórico, replay do ticket e auditoria completa.

Stack: React 18 + TypeScript + Vite + Supabase + PostgreSQL + IA (Claude/GPT/Gemini)

Horário de Funcionamento

Segunda a Sexta: 07:00 — 18:00

Sábado: 07:00 — 12:00

Pausa Automática: Ambos (cliente sem resposta + ticket inativo)

Feriados: Municipais + Nacionais automáticos

RN-002: Regras de SLA

# Regra Prioridade
1SLA inicia quando ticket entra em "Fila"Alta
2SLA pausa em "Aguardando Cliente" e "Aguardando Terceiro"Alta
3SLA pausa fora do expediente (07:00-18:00 seg-sex, 07:00-12:00 sáb)Alta
4SLA pausa em feriadosAlta
5SLA retoma quando cliente respondeAlta
6SLA violado gera notificação automáticaMédia
7SLA violado escalate automaticamenteMédia
8Cliente Premium: SLA × 0.5Alta
9Cliente Básico: SLA × 1.5Alta
10Board N2: SLA × 2.0Alta

RN-003: Regras de IA

# Regra
1IA responde em até 30 segundos
2IA classifica automaticamente em até 5 segundos
3IA escala para humano após 3 tentativas
4IA não fecha ticket sem confirmação
5IA registra todas as interações
6IA aprende com correções de operadores
7IA detecta sentimento a cada 5 mensagens
8IA gera nota de encerramento automática
9IA sugere respostas para operadores
10IA rastreia custo por interação

🔒 Políticas de Segurança (RLS)

Row Level Security — Supabase

-- ticket_events
ALTER TABLE ticket_events ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view events for accessible tickets"
  ON ticket_events FOR SELECT
  USING (
    ticket_id IN (
      SELECT id FROM tickets WHERE
        assignee_id = auth.uid()
        OR usuario_id = auth.uid()
        OR EXISTS (
          SELECT 1 FROM user_departamentos ud
          WHERE ud.user_id = auth.uid()
          AND ud.departamento_id = tickets.departamento_id
        )
        OR auth.jwt() ->> 'role' IN ('admin', 'gerente')
    )
  );

CREATE POLICY "System can insert events"
  ON ticket_events FOR INSERT
  WITH CHECK (true);  -- Service role only

-- Regra de auditoria: INSERT only
-- Criar trigger para bloquear UPDATE/DELETE
CREATE OR REPLACE FUNCTION prevent_audit_update()
RETURNS TRIGGER AS $$
BEGIN
  RAISE EXCEPTION 'Auditing tables are INSERT only. UPDATE and DELETE are prohibited.';
  RETURN NULL;
END;
$$ LANGUAGE plpgsql;
